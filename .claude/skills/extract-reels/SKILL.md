# Extract reels — subtitle-driven hook cutting

Turns `final.mp4` + its master subtitles into **≥5 vertical reels (1080×1920, 9:16, 20–40 s)** ready for Shorts/Reels/TikTok. Output goes to `reels/` (gitignored media, like `processed/` and `manim/`). No burned captions — clean video + animated end card only.

**Source of truth:** `.remotion/out/final.srt` (preferred) or `final.mp4`'s embedded cues. Never invent timings — every cut lands on a real `.srt` cue boundary (cut on speech, never mid-word).

## Inputs / preconditions

| need | where | how to ensure |
|---|---|---|
| final video | `final.mp4` at repo root (or `.remotion/out/final.mp4`) | Remotion export via `final-video` skill; verify with `ffprobe` — expect 2048×1280 @ 30 fps |
| master subtitles | `.remotion/out/final.srt` | Generated by `python3 scripts/build_master_subtitles.py` (after `scripts/build_timeline_manifest.py`). Fallback: `processed/*.srt` concatenated |
| timeline manifest | `.remotion/src/timeline-data.json` | Same step as above — used only to confirm total duration |

If `.remotion/out/final.srt` is missing, build it first:

```bash
python3 scripts/build_timeline_manifest.py   # if timeline-data.json is stale
python3 scripts/build_master_subtitles.py
ffprobe -v error -show_entries format=duration -of default=nw=1:nk=1 final.mp4
cat .remotion/out/final.srt | head -n 30
```

## Aspect ratio — 9:16 from 8:5 source

Final delivery is **2048×1280 (8:5)**. Reels must be **1080×1920 (9:16)**.

- **No stretching.** Center-crop the relevant region, then scale up.
- Source height is 1280 — keep it. 9:16 at 1280 high is **720 px wide** (`1280 * 9/16 = 720`). Crop `720:1280` centered: `crop=720:1280:664:0` where `664 = (2048-720)/2`, then `scale=1080:1920:flags=lanczos` (×1.5). This preserves pixel density and never softens monospace text with a non-uniform scale.
- `setsar=1` after scaling — prevents anamorphic SAR drift on some players.

See `docs/remotion-video-guidelines.md` §1 for why the project ships 8:5 and why this crop is the correct inverse.

## Hook discovery — what earns a reel

A reel needs a **self-contained hook** that works without the rest of the video. Analyse `final.srt` (and skim `final.mp4` at those times) for beats that have **at least two** of:

- **Curiosity gap / reversal** — "You think you know how torrents work. Let me show you..."
- **Strong open** — question, challenge, or bold claim in the first 2 s ("we don't know where the damn data is", "that guy is a very dumb guy")
- **Tangible number or contrast** — "50 people yelling at you", "512 kb", "20–30 peer connections", "same guy again and again"
- **Named mechanism** — tracker, peer explorer, deduplication, piece manager, event loop, 512 kb pieces → blocks
- **Payoff within 40 s** — the answer lands before the reel ends; no cliffhanger that needs external context

**Exclude:** mid-explanation slices that assume prior context, code walkthroughs that need reading time > 10 s, and any stretch that only makes sense after the previous 2 minutes.

**Timing rules (hard):**

- Reel length **20–40 s total** (body 16.5–36.5 s + 3.5 s end card). Ideal 22–35 s total; YouTube Shorts caps at 60 s but these are tighter.
- **At least 5 reels** — pick 5–8. Prefer 6 over 5 if the material supports it.
- Cuts **on cue boundaries** from `final.srt` — never mid-cue/mid-word. Pad `+0.20 s` before first cue and `+0.30 s` after last cue for breath (clamped to neighbours).
- **No overlap > 5 s** between reels — each hook should be distinct.
- No burned captions — viewers get clean video.
- Total coverage should not exceed 60% of the final video.

The helper `scripts/extract_reels.py` implements these heuristics and prints a scored table. Trust its timings over eyeballing.

## End card — "full video in description"

Every reel ends with a **3.5 s animated end card, 1080×1920**, Catppuccin Mocha + Fira Code (same as `EndCard2` / `catppuccin.py`), with e.g.:

```
Full video on YouTube
Link in description  ↓
[optional channel / video title line from manifest]
```

Requirements:

- Text is **animated** (spring `scale` + `interpolate` fade/slide, clamped — see `docs/remotion-video-guidelines.md` §5). No static hold.
- Rendered via Remotion composition `ReelEndCard` (1080×1920 @ 30 fps) or via the ffmpeg fallback in `extract_reels.py` if Remotion is unavailable. Either way the card is **concatenated**, not overlaid.
- Card audio: silence or a soft tail of the music bed ducked to −24 LUFS — never a hard cut mid-word.

## Workflow

### 1. Analyse — find hooks

```bash
python3 scripts/extract_reels.py analyse \
  --srt .remotion/out/final.srt \
  --video final.mp4 \
  --count 6
# defaults: --min-duration 16.5 --max-duration 36.5 (20–40 s total with 3.5 s card)
```

Prints a table like:

```
#  start     end       dur  score  hook (first cue)
1  00:00:13  00:00:45  32s  0.92   "You think you know how torrents work..."
2  00:01:21  00:01:58  37s  0.88   "that guy is a very dumb guy. He gives..."
...
```

Tweak `--count` or manual `start`/`end` if a hook feels off. **Show the table to the user and confirm before cutting** — re-cutting is cheaper than re-rendering.

Scoring (in the script): `score = hook_strength * payoff_density * self_containment` where hook_strength looks for question/reversal/number in the first 2 cues, payoff_density counts explanatory cues in the window, self_containment penalises unresolved pronouns ("this", "that guy" without antecedent in-window).

### 2. Cut — render vertical reels

```bash
python3 scripts/extract_reels.py cut \
  --srt .remotion/out/final.srt \
  --video final.mp4 \
  --out reels/
```

This for each reel:

1. Runs `ffmpeg` with vertical crop/scale (no burned captions):
   ```
   -ss <start> -t <body_dur> -i final.mp4
   -vf "crop=720:1280:664:0,scale=1080:1920:flags=lanczos,setsar=1"
   -c:v libx264 -pix_fmt yuv420p -crf 18 -preset medium
   -c:a aac -b:a 128k
   ```
   Hardware path: if `h264_nvenc` is available, the script uses it (`-c:v h264_nvenc -cq 19`).
2. Renders or reuses the 3.5 s end card (`reels/.tmp/reel-endcard.mp4` — 1080×1920, Remotion `ReelEndCard` if `npx remotion` is available, otherwise ffmpeg `color` + `drawtext` fallback).
3. Concatenates via `ffmpeg -f concat` → `reels/reel-0N-<slug>.mp4` (20–40 s total).

### 3. Verify — before handing over

```bash
for f in reels/reel-*.mp4; do
  echo "=== $f ==="
  ffprobe -v error -select_streams v:0 -show_entries stream=width,height,codec_name,avg_frame_rate -of default=nw=1 "$f"
  ffprobe -v error -show_entries format=duration -of default=nw=1:nk=1 "$f"
done
# Spot-check
ffplay reels/reel-01-*.mp4  # or mpv, check first 2s hook + last 4s end card
```

Checklist (mirror `docs/remotion-video-guidelines.md` §10 for reels):

- [ ] ≥5 files in `reels/` matching `reel-0N-<slug>.mp4`
- [ ] Each is **1080×1920**, 30 fps, h264 `yuv420p`, AAC, **20–40 s** total (body + 3.5 s card), no burned captions
- [ ] First spoken word lands ≤ 0.5 s in; hook is audible/visible immediately
- [ ] End card renders for full 3.5 s, text animated (not frozen), CTA reads "Full video — link in description" (or equivalent)
- [ ] No reel reuses > 5 s of another reel's window
- [ ] Audio never cuts mid-word; peak < 0 dBFS

### 4. Report

Tell the user:

- `reels/` file list with `duration` and `hook` line (from the analyse table)
- Total runtime vs final
- That `reels/` is gitignored media — `final.mp4` + `.remotion/out/final.srt` are the reproducible source

## Remotion end card (optional but preferred)

`ReelEndCard` lives at `.remotion/src/compositions/ReelEndCard.tsx` (1080×1920, 30 fps, 105 frames = 3.5 s). Registered in `.remotion/src/Root.tsx` as `ReelEndCard`. Render once and reuse:

```bash
cd .remotion && npx remotion render ReelEndCard out/reel-endcard.mp4 --concurrency=4
cp out/reel-endcard.mp4 ../reels/.tmp/reel-endcard.mp4
```

The composition mirrors `EndCard2` but vertical: progress shimmer → headline spring → subline fade, Catppuccin `base`→`mantle` gradient, `FONT` = Fira Code. See that file for the exact `spring`/`interpolate` (clamped) values.

## Gotchas (read before debugging)

- **Never use `scale` on the source before `crop`** — you'd resample then discard pixels and soften code glyphs. Crop first.
- **Do not reuse the 2048×1280 end card** — it's 8:5 and will pillarbox inside 9:16. Render the 1080×1920 one.
- **No burned captions** — the video is clean; end-card is the only text layer.
- **`-ss` placement:** `-ss` before `-i` is fast but seek-inaccurate; the script uses `-ss` before `-i` for coarse seek. Do not move `-ss` after `-i` without also adjusting the concat demuxer's duration.
- **Concurrency:** Remotion's Chromium workers are CPU/RAM-bound. Keep `--concurrency=4` for end-card renders on 15 GiB RAM; NVENC reels can run at `--jobs 2` concurrently.

## One-liner (happy path)

```bash
python3 scripts/extract_reels.py analyse --count 6 && \
python3 scripts/extract_reels.py cut --out reels/ && \
ls -lh reels/reel-*.mp4 && \
for f in reels/reel-*.mp4; do ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of csv "$f"; done
```
