# YouTube Template

Repo for producing YouTube videos: scripts + asset directories, one project per video.

## Directory layout

- `scripts/` — automation scripts (rendering, encoding, uploads, etc.)
- `manim/` — rendered Manim clips (output). Actual Manim project source lives in `.manim/`.
- `remotion/` — rendered Remotion clips (output). Actual Remotion project source lives in `.remotion/`.
- `raw/` — raw screen/camera recordings, unedited
- `processed/` — video processed/edited from `raw/`
- `screencasts/` — screen recordings, taken manually by user (no automated capture tooling)
- `audio/` — audio tracks (voiceover, music, SFX)
- `memes/` — meme assets
- `video_clips/` — short clips dropped in by hand for a plan to draw on
- `plans/` — planning docs for videos/features, including `plans/hook.md` (the opening 30 seconds; per-video, gitignored)
- `docs/` — standards: `manim-layout-guidelines.md`, `remotion-video-guidelines.md`
- `progress.md` — this video's todo list and working log (per-video, gitignored)

## Machine spec

See `SPEC.md` for CPU/GPU/RAM/disk. Key constraint: 4 GiB VRAM (RTX 3050 Laptop) — keep render concurrency low, check nvenc/CUDA tools bind to NVIDIA not Intel iGPU.

ggml-based tools (whisper.cpp) need the backend packages `ggml-cpu` + `ggml-cuda` installed alongside `ggml` — the base `ggml` package ships no compute backend and aborts in `ggml_backend_dev_backend_reg`. Whisper models live in `~/.local/share/whisper.cpp/models/`.

Always prefer NVIDIA GPU for video processing (encode/decode/render), not Intel iGPU or CPU-only. E.g. ffmpeg use `-hwaccel cuda` / `h264_nvenc`/`hevc_nvenc`; force `prime-run` where needed.

## Conventions

- **This repo is a template: only what is generic to *any* video is tracked.** `.gitignore` is the authority and is grouped to say which side of that line each thing falls on. Committed = the engines and the rules (`scripts/`, `.claude/skills/`, `docs/`, `.remotion/src/` except `compositions/`, `.manim/scenes/design.py`, the configs). Ignored = one episode's content (all media dirs, **every binary media file anywhere, by extension**, `.manim/scenes/*.py` other than `design.py`, `.remotion/src/compositions/*` other than `Hook.tsx` and `ReelEndCard.tsx`, `scripts/build_timeline_manifest.py`, `scripts/build_hook_manifest.py`, `.remotion/src/timeline-data.json`, `.remotion/src/hook-data.json`, `plan.md`, `progress.md`, `plans/*` (incl. `plans/hook.md`), `final.*`). When you write something reusable, put it on the tracked side rather than leaving it inside an episode's file.
- **`progress.md` is the todo list for the video in flight**, not a permanent record: what is still outstanding, what is done, what is blocked. Create it if absent. It is gitignored, so anything worth keeping past this episode must be **promoted** — a recurring rule goes in CLAUDE.md, a technique goes in `docs/` or the relevant skill. A lesson left only in `progress.md` is lost with the episode.
- `.manim/` and `.remotion/` hold actual project source (configs, scenes, components); `manim/` and `remotion/` hold their rendered output only.
- **`.remotion/src/compositions/` is per-video and gitignored; `.remotion/src/components/` is template and tracked.** This is the same split as `.manim/scenes/*` vs `design.py`, for the same reason: `remotion-clip` writes one composition per clip, so that directory fills with an episode's title cards, charts and code shots. Only `Hook.tsx` and `ReelEndCard.tsx` are negated back in, because they are structural — the opening `hook-build` renders and the vertical CTA `extract-reels` appends. **When a composition contains something reusable, lift it into a component**, which is the tracked side; a clip left whole in `compositions/` is lost with the episode.
- **Manim is for MATHEMATICAL animation only — everything else is Remotion, *including plots, charts and diagrams*.** The test is whether the subject IS mathematics: a function being plotted and transformed, an equation rearranged, a geometric argument. That is what Manim is uniquely good at. A plot of *measured data* is Remotion; a plot of a *function being reasoned about* is Manim. Architecture diagrams, bar charts, timelines, title cards, kinetic type and code are all Remotion — for those, Manim costs a CPU-bound Cairo render and a round trip through a file, where a Remotion component composes directly at 2048px and re-encodes nothing. When in doubt it is Remotion; reach for `manim-clip` only when the maths is the point.
- **`DESIGN.md` at the repo root is the design authority for the whole video, and it is READ, not parsed.** A design system is judgement — "the accent is functional, never decorative", "thin shadows are invisible on dark" — and none of that survives a token extractor. Read it before writing any Remotion composition or Manim scene, the same gate as `docs/manim-layout-guidelines.md`. It lands in exactly two hand-authored files: **`.remotion/src/design.ts`** and **`.manim/scenes/design.py`**, which hold the palette, semantic roles, type scale, spacing, elevation, zones and motion counts. Swap `DESIGN.md`, update those two, re-render — there is no third place to look. `scripts/check_design.py` fails the build on a raw hex or a bare font size anywhere else.
- **The dependency runs DESIGN.md → `design.ts`/`design.py`, and it is easy to run it backwards without noticing.** `check_design.py` only proves a component imported a token; it cannot tell whether that token is in the design document at all. So new values accumulate in `design.ts` — a new zone, a new scrim direction, a whole archival grade — each justified in a code comment that *argues against* a section of DESIGN.md rather than amending it. That is exactly section 11's "no third place to look" being violated, with the code as the third place. When a design decision is genuinely new, or genuinely an exception to a rule §10 states flatly, **write it into DESIGN.md first** and have the token cite the section. A code comment overriding the authority is a fork, not a note.
- **Source of truth for technical content: `/home/piyush/Projects/dhaar-torrent`** (the Rust/Tokio torrent client this series is about). Check component names, topology and constants against its `README.md` "Architecture" section and `src/` tree — the narration alone is not reliable (it never mentions `request_manager`, and calls `PieceWriter` a "disk writer").
- **Code clips are built in Remotion** (`remotion-clip`), not Manim. Code shown in them must be REAL source pasted from that repo, with elisions marked `// ...` — invented-but-plausible code undermines the video. Keep a snippet under ~28 lines and hold it 2.5s + 0.3s per line; 27 lines of Rust wants ~12s. Verify bracket balance before rendering: a stray bracket once put broken code on screen. Highlighting must match `DESIGN.md` section 10.9.
- Code blocks use `CODE_FONT` (auto-detected), NOT Fira Code: Fira Code's `//` ligature desyncs Manim's per-character glyph mapping and crashes `Code()` with `IndexError` in `_gen_chars`. Installing `ttf-fira-mono` upgrades code blocks to the matching ligature-free Fira face; until then they fall back to another mono. Display text keeps Fira Code, where the ligatures are desirable.
- Manim layout follows `docs/manim-layout-guidelines.md` (30 rules). The load-bearing ones: express position as RELATIONSHIPS not coordinates (S2/S28), use the `GAP_*` spacing scale rather than ad-hoc `buff=` values (S9), attach labels to their objects (S11), keep established objects still so the viewer's spatial map survives (S7/S19), dim context so the new component dominates (S16), and run the validation pass before shipping (S22).
- Generated clips must pass `audit_layout()` (in `.manim/scenes/design.py`) — it raises `LayoutError` if a mobject overflows the frame or two collide. Quick check: `cd .manim && manim render -s scenes/<file>.py <Scene>`. The audit does not replace looking at a rendered frame; it catches overflow/collision, not "an arrow crosses this paragraph".
- Semantic colour roles come from `DESIGN.md`: `text` body, `textMuted` captions and sub-headlines, `textFaint` de-emphasised, `accent` state/success and the component under discussion (**functional only — never decorative**), `warning`, `error`, `info` for data and links, `surface`/`elevated` for raised panes, `border` for hierarchy, `scrim` behind text. The frame is otherwise achromatic on purpose: the footage supplies the colour.
- **No binary media is tracked, from anywhere — `.gitignore` enforces it by extension, not only by path.** `video_clips/` was once the single tracked asset dir, on the theory that a short hand-dropped clip should travel with the repo; that is reversed, and it is ignored like every other. The reason the exception did not hold: git history for a binary is permanent and one-way, so the rule has to be checkable rather than a promise to keep files "small", which nothing enforced. The extension list (`*.mp4`, `*.wav`, `*.png`, `*.srt`, …) is the backstop that catches a new asset dir or a stray render nobody added a path for. Committing one is now a deliberate act: `git add -f`.
- Keep raw recordings in `raw/` untouched; edits go to `processed/`.
- False starts / flubbed takes go to `raw/discarded/` rather than being deleted — both pipeline scripts glob `raw/*.mkv`, so a subdirectory is excluded automatically. `raw/discarded/README.md` records why each was dropped and what superseded it.
- **Audio must be free — no paid licences, subscriptions or per-track purchases.** `find_audio.py` enforces an allowlist: only CC0/public-domain and plain CC-BY pass; NC, ND, SA, Sampling+ and anything unrecognised are rejected. Prefer the YouTube Audio Library (free, no Content ID risk, mostly no attribution) or Pixabay over Jamendo, whose catalogue is mostly NC and which sells commercial licences separately.
- **An SFX imported at -6 dBFS peak needs POSITIVE `gain` to be the loudest thing in a mix.** `find_audio.py import --role sfx` peak-normalises to -6 dBFS, while a raw archival voice mp3 peaks near -4 — so a "loud" cue written at `gain: -1` lands 3-4 dB *under* the dialogue. This bit twice on the same hook: once from a weak synth source, once from the normalisation. Set the gain from a measurement of the render, never from intuition about the number's sign.
- **Integrated LUFS is the wrong yardstick for anything containing deliberate silence.** A hook with two held silences measured -17.7 LUFS overall while its speech was correctly at -16.8. Measure the *speech windows* (`ffmpeg -ss X -to Y -af ebur128`) and let the silences be silent. Same reason single-pass `loudnorm` must never touch such a mix: it is dynamic and pumps gain into the gaps.
- **A beat's own `sfx` are clipped to that beat by its `<Series.Sequence>`.** Anything crossing a cut — a voice take spanning three beats, a 7.6 s riser under a 2.8 s beat — is silently truncated and must go on the hook-level `voice`/`beds` track (absolute `atSec`), not into a beat. `hook_lib.build_audio()` is that track.
- Audio levels are anchored on the narration: `process_recording.py` masters it to -16 LUFS (measured -16.2), music beds import at -20 LUFS, SFX at -6 dBFS peak. Still duck the bed 6-9 dB under speech in the Remotion composition — import levels are a starting point, not a mix.
- `memes/PLACEMENT.md` maps each meme to the transcript beat it belongs on; `memes/CREDITS.md` holds attribution. Both are written by tooling, both are gitignored with the rest of `memes/`.
- Use the `.mp4`/`.mov` from `memes/`, never the `.gif` — GIF per-frame delays drift against a fixed-fps timeline and palette transparency gives hard edges. In Remotion load them with `<OffthreadVideo>` (server-side FFmpeg, so ProRes works); transparent stickers need `transparent={true}`, which costs ~40% render time. `memes/CREDITS.md` tracks attribution.
- Subtitles live as sidecar `.srt` next to their clip in `processed/` (same basename). Do NOT burn them in — upload the `.srt` to YouTube, which is searchable and translatable. Cue **boundaries** are the authority for cutting on speech boundaries and for ducking the music bed — but positions *inside* a cue are not (see the waveform rule below).
- **Transcribe `raw/` FIRST, then cut with `--pauses-from`.** This inverts the old rule ("transcribe `processed/`, never `raw/`"), which existed because cutting shifted timestamps. It no longer has to: `process_recording.py --pauses-from <raw.srt>` reads the transcript to decide which silences are performance, and then **remaps the cues through its own cut map** onto a sidecar `.srt` beside the output. So `processed/*.srt` is generated by the cut, matches it exactly, and costs no second whisper pass. Never transcribe `processed/` separately — that is how a sidecar ends up silently describing the uncut source.
- **The first ~30 seconds is the hook, and it is planned and built separately.** `plans/hook.md` is the authority on what it is (dedicated take / cold-open montage / motion graphics / mix); `hook-plan` writes that file from the user's own idea, `hook-build` implements it and invents nothing. The hook is its own Remotion composition (`Hook`), free to break body rules the plan explicitly suspends — text at frame centre is legal there, because the hook may have no speaker at all. `combine-all` joins it to the body at the end; it is deliberately not a segment inside `FinalVideo`, so those freedoms cannot leak into the body.
- **A pause is not the same thing as dead air, and duration alone cannot tell them apart.** `scripts/pause_lib.py` classifies each gap from the words either side: a completed sentence before it or a reversal after it means performance (keep); trailing off mid-clause, or backing up and repeating the same words, means hesitation or a flub (cut). **Ambiguous gaps are kept** — a pause wrongly kept costs a beat of dead air, a pause wrongly cut destroys a delivery and needs a re-encode from raw to recover. The `.srt` is also a better *measurement* than `silencedetect`: whisper runs with `-sow -sns`, so cue boundaries land on real speech rather than a −30 dB amplitude threshold that room tone and keyboard noise trip.
- **Pick an edit point from the WAVEFORM, never by interpolating `.srt` cue times — and a transcript cannot check your work.** `word_timeline()` spreads a cue's words evenly across its duration, so a word's reported time is a *fiction* wherever the speaker paused: cue boundaries are real, positions inside a cue are not. Three of four in/out points chosen that way landed mid-syllable, one audibly (−17.3 dB — the middle of a loud word). The trap is that **whisper discards a clipped fragment**, so the good and bad versions of a trim transcribe identically and the defect survives every check that reads text. Use `silencedetect` plus a ~25 ms RMS profile and cut at the quietest sample; then confirm the *rendered* result, not the source. Corollary: if a clean entry does not exist, say so — continuous speech has no good cut, and the line you wanted may simply not be gettable.
- **Hook footage lives in `raw/initial/`.** Its pauses are the performance, so it is mastered either with `--pauses-from` (cut the ums, keep the beats) or `--no-cut` when `plans/hook.md` says every pause is load-bearing — the two flags are mutually exclusive. `--no-cut` masters (highpass + compressor + loudnorm + NVENC) without cutting anything, and switches loudnorm to two passes with `linear=true` — single-pass loudnorm is dynamic and ramps the gain up across a long pause, measuring 1.9 LU hot on an 8s clip with one 4s pause. Trim belongs in the beat's `startFromSec`/`toSec`, non-destructively, not burned into the file.
- **The hook transcribes `raw/`, the one exception to the `processed/`-only rule** — that rule exists because silence-cutting shifts timestamps, and the hook is never silence-cut. But once `hook-build` splits or trims the take, **regenerate the `.srt` per produced piece**: the raw one then describes nothing on disk, and `check_text_not_early()` would validate against the wrong timeline.
- The hook's duration is **composed from its beats**, never derived from one recording's length. A beat's `source` is optional — omit it for a title card or chart and give `durationSec`. `scripts/hook_lib.py` is the tracked engine; `scripts/build_hook_manifest.py` is this episode's plan and is gitignored, exactly like `timeline_lib.py` / `build_timeline_manifest.py`. `python3 scripts/hook_lib.py --stub` writes placeholder manifests so the template works with no episode content.
- **Final assembly is done in Remotion, not manually.** `.remotion/` holds the composition that stitches `processed/`, `manim/`, `memes/` and `audio/` into the finished video; `docs/remotion-video-guidelines.md` is the standard. The flow is five skills, in this order: `main-plan` → `main-build` for the body, then `hook-plan` → `hook-build` for the opening, then `combine-all` to join them and build the master `.srt`. **The body is planned first** — the hook advertises what the body contains, so you cannot promise before you have decided. If a hook gets written first anyway, the body must pay it off; reconcile the two plans rather than shipping a promise the video never keeps. Kdenlive is no longer used.
- The composition is data-driven, never hand-typed frame numbers, and split **template vs per-video**: `scripts/timeline_lib.py` is the reusable engine (srt parsing, word-onset maths, the validators, ffprobe duration/dimension probing, manifest writing) and is part of the template; `scripts/build_timeline_manifest.py` is **this video's editorial plan only** (which cutaway/gif/punch line/emoji goes where) and is gitignored. Running the plan writes `.remotion/src/timeline-data.json` (also gitignored — it embeds facts about gitignored media, regenerate after any asset change). `scripts/build_master_subtitles.py` offsets each segment's own `.srt` into one master `.remotion/out/final.srt` for YouTube upload — it reads `hook-data.json` too, so the body's cues are shifted by the hook's real duration and a hook beat's cues are shifted for its own trim. The hook's editorial engine/plan pair is `scripts/hook_lib.py` + the gitignored `scripts/build_hook_manifest.py`, writing `.remotion/src/hook-data.json`.
- **The build enforces the editorial rules; do not hand-eyeball them.** `python3 scripts/build_timeline_manifest.py` fails or reports on: text appearing before it is spoken (`check_not_early`), a gif used more than once (`check_no_repeated_gifs`), a cutaway starting at/after its segment's end so it could never render, and any stretch outside a cutaway with nothing on screen (`report_coverage`). Every one of these caught a real defect that eyeballing had missed.
- **On-screen text is three layers with distinct jobs** — captions (every spoken word, from the `.srt`, bottom band, normally only the opening beat), punchTexts (selected emphasised lines, lower third), stamps (short concept labels, top banner, the only layer that is not a quote). Nothing says the same words twice, and **nothing is placed at frame centre** — that is where the speaker's face is. Full details and the reasoning in `docs/remotion-video-guidelines.md`.
- **Nothing may be drawn on top of a cutaway** — Manim *or* screencast. A cutaway is the content being shown; a meme inset once covered a `sha256sum` digest and an emoji covered `digest == piece.hash`. `CutawaySafeSequence` enforces it, which also means a layer scheduled inside a cutaway window renders as nothing at all — check for that.
- **A gif is used at most once per video**, and must be rendered composited into a real frame and looked at before it is trusted: a GIPHY title is not evidence of provenance (two titled plainly `robot GIF` / `Happy Robot GIF` were both Bender from Futurama). Emoji may repeat only where the repeat means something.
- Don't freeze a short Manim clip across a long window to fill time — a 1.7 s clip held for 25 s looks dead and blocks every overlay for those 25 s. Shrink the window to the clip's real length plus a beat. If a diagram is needed at two separate points in the narration, **split the scene into two clips** rather than holding one; share a base class so the geometry cannot jump between them.
- `Config.setPublicDir('..')` in `.remotion/remotion.config.ts` points Remotion's `staticFile()` at the repo root, so `processed/`, `manim/`, `memes/`, `audio/`, `screencasts/` are all reachable with zero file copying — confirmed empirically (the docs are ambiguous on parent-directory support) by rendering a still that both resolved the path and decoded a real frame via `<OffthreadVideo>`.
- Two Remotion gotchas worth knowing before touching the composition: (1) `Config.setCrf()` alongside hardware acceleration makes Remotion **silently fall back to software encoding** ("crf option is not supported with hardware acceleration") — never set both; verify with verbose logging (`Encoder: h264_nvenc, hardware accelerated: true`), not by assuming. (2) `<Loop>` defaults to the same absolute-fill layout as `<Sequence>` and needs an explicit-**height** parent, not just a width — pair `layout="none"` on `<Loop>` with a real per-asset `aspectRatio` (never guess one; a wrong guess crops square/near-square memes).
- Manually filtering with `.find()`/`.filter()` to pick an "active" cutaway/overlay does **not** give the child component a shifted time origin — `useCurrentFrame()` only resets inside an actual `<Sequence>` ancestor. Always wrap each timed element in its own `<Sequence from={...} durationInFrames={...}>` and let Remotion's own visibility handling do the work.
- A meme's GIPHY title is not enough evidence of low copyright risk — render it composited into the actual frame and look, don't just read the title. Two picks that sounded generic ("Confused No Idea GIF by Bounce", an "impatiently at his watch" clip) turned out to carry a network watermark/burned-in captions and an identifiable soap-opera actor from the show's own official channel, respectively, only visible once actually rendered in place.
- **Record screencasts at 3072x1920 — exactly 1.5x the delivery frame, same 8:5 ratio.** This is the cheapest quality win available: a 2048x1280 crop out of a 3072x1920 source is a **1:1 pixel window**, so focus pans and punch-ins up to 1.5x involve no resampling at all. §10.7's "never scale a source" is then *honoured*, not suspended — its stated reason is that rescaling softens monospace glyphs, and at <=1.5x nothing is rescaled. `timeline_lib.build_focus()` enforces the ceiling and warns when a source is too small to sustain the requested zoom. A talking-head take at native 2048x1280 has **no** such headroom, so punch-ins there are true upscales: cap them at ~1.2x, ration them to emphasis lines, and rely on cutaways for rhythm instead.
- **Anchor a component's exit animation to the END of the window it is given, never to a fixed frame.** `Stamp` faded out over frames 25→35 while `NarrationSegment` handed it a 30-frame sequence, so every stamp in the body was hard-cut in the middle of its own fade — and `Hook.tsx` had already papered over it locally with `durationInFrames={35}` plus a comment saying "the body still uses 30". A layer's lifetime is a **design value**: `MOTION.minTextFrames` (60 = DESIGN.md §10.8's 2 s floor) is the single source, and the component derives its ramp from the duration prop. Two files disagreeing about how long a layer lives is the bug, not the number.
- **The YouTube Audio Library is reachable without a login** via the static index at `thibaultjanbeyer.github.io/YouTube-Free-Audio-Library-API/api.json` — 5,142 mp3s on Google Drive, downloadable at `drive.google.com/uc?export=download&id=<id>` (the index's own `export=open` URL is a preview link). The files carry ID3 `artist`/`title` and `album=YouTube Audio Library`/`encoder=Google`, which is real provenance evidence. **They carry no licence field**, and the catalogue includes Kevin MacLeod tracks that are CC-BY in origin, so the policy is: **credit every track from this index as CC-BY**. Crediting one that did not need it costs a line; missing one that did is a violation. It is a dated snapshot on a third party's Drive — pull what an episode needs now rather than depending on it later. `yt-dlp` against "no copyright music" channels remains off-limits: mislabelled and Content-ID-claimed.
- **Delivery is 2048x1280 (8:5), the recorder's native ratio** — deliberately not 16:9. Nothing is scaled, cropped or framed, so screencasts and code clips stay pixel-perfect (rescaling softens small monospace glyphs). YouTube pillarboxes 8:5 on a 16:9 player, ~5% of width each side; that is the accepted trade. Never scale a full-frame source in the composition, and keep `.manim/manim.cfg` at 2048x1280.
- Export on the GPU: Remotion's bundled FFmpeg has NVENC on Linux x64 for h264/h265 only. `Config.setHardwareAcceleration('if-possible')` is set in `.remotion/remotion.config.ts`; pass `--hardware-acceleration=required` on a real export so a silent fall back to CPU fails loudly.

## Scripts

- `scripts/trim_to_short_video.sh <video1> <video2> <output>` — keep first N min of video1, concat video2 after it. NVENC/CUDA-accelerated (GPU decode+encode). Handles mismatched resolution/fps via scale+pad filter.
- `scripts/process_recording.py <input> [output]` — raw/ → processed/ pipeline. Cuts silent gaps >=1s (video+audio stay in sync), then cleans audio (highpass, compressor, loudnorm EBU R128) for loud/clear podcast-style sound. Video encoded with h264_nvenc (GPU). `--pauses-from <srt>` keeps the pauses the transcript says are deliberate and writes the remapped `.srt` beside the output; `--no-cut` keeps every pause and masters only (two-pass linear loudnorm). The two are mutually exclusive.
- `scripts/find_audio.py {import|search|download}` — audio into `audio/`. `import <file> --role music|sfx` needs no API key and normalises on the way in (music → -20 LUFS, sfx → -6 dBFS peak with silence trimmed); `search`/`download` use Jamendo (music) / Freesound (sfx). Keys via env var or gitignored `.env`. **NonCommercial and NoDerivatives licences are filtered out** — a monetised video is commercial use and ducking/trimming is a derivative. Attribution goes to `audio/CREDITS.md`.
- `scripts/find_memes.py {convert|search|download}` — reaction GIFs / transparent stickers into `memes/`. `convert <file-or-url>` needs no API key and is the primary path; `search`/`download` use GIPHY (free Beta key `GIPHY_API_KEY` in the gitignored `.env`, 100 calls/hour). Saves the original plus an edit-ready render — transparency is **detected from the file**, opaque → mp4 via NVENC, transparent → ProRes 4444 `.mov` with alpha (CPU-only; NVENC cannot encode alpha). Provenance goes to `memes/CREDITS.md`. **Tenor is unusable — Google stopped issuing new API keys in Jan 2026.**
- `scripts/pause_lib.py` — classifies each silence as performance or dead air from the words either side (`pause_plan`, `classify_gap`, `protected_windows`), and remaps cue times through a cut map (`remap_cues`). Template engine behind `--pauses-from`. Ambiguous gaps are KEPT by design.
- `scripts/srt_lib.py` — the one `.srt` reader/writer (`read_srt`, `write_srt`, `Cue`), shared so three copies of a subtitle parser cannot drift apart.
- `scripts/generate_subtitles.sh [file ...]` — transcribes clips into sidecar `.srt`. **Pass `raw/*.mkv` explicitly** — the bare default still globs `processed/`, which the pause-aware flow no longer needs (whisper.cpp large-v3-turbo on GPU via ggml-cuda). Defaults to all of `processed/*.mkv|mp4`, skips clips that already have an `.srt` unless `--force`. Overridable via `WHISPER_MODEL` / `LANG_CODE` / `MAX_LEN` / `PROMPT` env vars; the default `PROMPT` biases BitTorrent vocabulary so accented speech resolves domain terms correctly.

## Skills

- `main-plan` (`.claude/skills/main-plan/`) — plans the body: runs `process-recording` over `raw/`, reads every transcript, then works out spine / theme / visual language **with the user** and writes `plans/main.md`. Names the engine for each visual (Manim only for mathematics) so `main-build` never guesses. Confirms the spine before anything is generated.
- `main-build` (`.claude/skills/main-build/`) — implements `plans/main.md`: generates the clips, runs `meme-pass` and `audio-pass`, writes `scripts/build_timeline_manifest.py` → `.remotion/src/timeline-data.json`, exports `FinalVideo` with `--hardware-acceleration=required`. Refuses to run on a missing or incomplete plan; trusts the build gates over eyeballing.
- `combine-all` (`.claude/skills/combine-all/`) — joins hook + body into `final.mp4` and builds `.remotion/out/final.srt` with the body offset by the hook's real duration. Uses the concat **filter** on NVENC, not `-c copy`: AAC's 1024-sample frames don't divide evenly into whole video frames, so stream-copying two parts leaves the audio ~21ms longer than the video at the seam.
- `hook-plan` (`.claude/skills/hook-plan/`) — plans the opening 30 seconds: transcribes the take from `raw/initial/`, sharpens **the user's own idea** into beats, writes `plans/hook.md`. Interrogates the promise, the open loop and whether the payoff actually exists later in the video. The user's taste leads; it invents no hook of its own.
- `hook-build` (`.claude/skills/hook-build/`) — implements `plans/hook.md` and nothing else: splits the take on the plan's boundaries, masters with `--no-cut`, regenerates each piece's `.srt`, writes `scripts/build_hook_manifest.py` → `.remotion/src/hook-data.json`, renders the `Hook` composition with `--hardware-acceleration=required`. Refuses to run on a missing or incomplete plan.
- `manim-clip` (`.claude/skills/manim-clip/`) — writes a Manim scene to `.manim/scenes/<clip_name>.py`, renders it (2048x1280 @ 30fps, set in `.manim/manim.cfg`), publishes the result to `manim/<clip_name>.mp4`. Manim's render is CPU-bound (Cairo) — the GPU-first rule above applies to the ffmpeg scripts, not to Manim itself.
- `remotion-clip` (`.claude/skills/remotion-clip/`) — writes a Remotion composition to `.remotion/src/compositions/<Name>.tsx`, registers it in `.remotion/src/Root.tsx`, renders it (2048x1280 @ 30fps default), publishes the result to `remotion/<clip_name>.mp4`. Render encode is CPU x264 (Remotion's bundled ffmpeg), not NVENC.
- `audio-pass` (`.claude/skills/audio-pass/`) — the layer above `find-audio`: sweeps the clips and transcripts for moments wanting a cue, writes `audio/PLACEMENT.md`. Prefers the YouTube Audio Library (no key, no Content ID risk) over the APIs. Watches SFX repeat counts — a cue used 6 times must be near-subliminal.
- `meme-pass` (`.claude/skills/meme-pass/`) — the layer above `find-memes`: sweeps all of `processed/*.srt` for beats that want a reaction shot, sources one per beat, writes `memes/PLACEMENT.md`. Targets ~1 beat per 60-90s and never puts a meme on an explanation stretch.
- `find-memes` (`.claude/skills/find-memes/`) — prefers converting a GIF the user found themselves (no API), falls back to GIPHY search. Picks search terms from the *emotion* of a beat rather than its topic. Covers the GIF-on-a-timeline pitfalls, alpha handling, and the attribution/copyright caveat.
- `find-audio` (`.claude/skills/find-audio/`) — sources ONE track or effect into `audio/`. Prefers `import` from the YouTube Audio Library (no key, no Content ID risk) over the Freesound/Jamendo APIs. Carries the free-only allowlist rule and the -20 LUFS / -6 dBFS level targets.
- `process-recording` (`.claude/skills/process-recording/`) — drives the two-stage `raw/` → `processed/` pipeline: `process_recording.py` (silence cutting + audio cleanup + NVENC encode), then `generate_subtitles.sh` (sidecar `.srt`). Documents the tuning knobs for both stages and why the order can't be reversed.
